# 보영하이텍 주물사 불량 예측

2026 지역특화 제조데이터 활성화 사업 「자동차부품 후처리 공정 제조데이터 기반 품질 예측 AI솔루션」 과제의 분석·학습 코드.

주조 전에 측정하는 주물사(모래) 시험값으로 **4G100 CUP 로트의 불량률이 기준을 넘을지** 판정하는 이진 분류 문제를 다룬다.

## 현재 상태 (2026-10-16)

| 항목 | 내용 |
|---|---|
| 데이터 | 2024-02 ~ 2026-09, 모래 시험과 불량 실적이 연결된 로트 529개 |
| 모래 시험값으로 예측 | **안 된다.** 3년 전체·연도별 모두 비교 기준(다수 쪽 판정)을 넘지 못한다 |
| 직전 로트 불량률로 예측 | 정확도 0.750 · AUC 0.77 (기준 2.95%, 비교 기준 0.682). 불량 집계를 매일 입력해야 쓸 수 있다 |
| 다음 단계 | 조형·주입·배합 등 공정 조건 데이터 확보 |

세부 결과는 [결과 요약](#결과-요약) 참고.

## 구성

```
pipeline/
  db.py                      DB 조회 (docker mysql 클라이언트, 조회 전용)
  preprocess.py              전처리 build() — 시험·불량 로트 연결, 로트 단위 집계
  classify.py                후보 모델 · 시간순 검증 · 판정 임계값 규칙
  predict.py                 학습 · 값별 판정 조회
  quantity.py                생산·불량 수량 집계
  export_csv.py              DB → CSV 내보내기

  1-데이터분석.ipynb           분포 · 결측 · 이상치 · 상관 · 계절
  1-데이터분석-전체기간.ipynb    2024~2026 전체 기간 분석 (모델링 없음)
  2-데이터전처리.ipynb          전처리 단계별 확인
  3-모델학습.ipynb             변수 선별 · 대조 실험 · 모델 비교
  4-모델성능평가.ipynb          시간순 검증 · 혼동행렬 · 상한 · 예측 확인
```

노트북 출력은 저장소에 올리지 않는다 (DB 데이터가 들어 있어서). 실행하면 다시 생성된다.

## 설치

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # DB 접속 정보 입력 (git 에 올리지 않는다)
```

- DB 조회는 `docker run mysql:8` 클라이언트를 거친다. docker 가 필요하다.
- 그래프의 한글은 NanumGothic 글꼴을 쓴다.
- **수치는 `requirements.txt` 의 버전으로 측정했다.** 판정 경계에 걸린 값이 있어 scikit-learn·xgboost 버전이 다르면 결과가 달라질 수 있다 (예: F1 0.531 ↔ 0.594).

## 실행

```bash
cd pipeline
jupyter nbconvert --to notebook --execute --inplace 1-데이터분석-전체기간.ipynb
python predict.py 26 27 28        # 벤토나이트 값별 판정
python export_csv.py              # DB → CSV
```

노트북은 DB 에서 바로 읽으므로 실행 시점의 데이터로 결과가 갱신된다.

## 데이터

DB `byht_db` (MySQL) 의 테이블 3개를 **조회만** 한다.

| 테이블 | 내용 | 갱신 |
|---|---|---|
| `foundry_test_result` | 주물사 시험 — 모래온도, 수분, 충진율, 압축·전단강도, 통기도, 충진시편·표준시편 무게, 벤토나이트 투입량 | 매일 |
| `bad_statistics` | 로트별 생산·불량 수량, 불량 유형 (사혼입·중자·미충진·몰드크랙 등) — 정답 | 월 1회 일괄 |
| `dc_ingg_meas` | 트리밍 치수 측정 — 주조 후라 입력으로 쓰지 않음 | 매일 |

**로트 연결 규칙** (`preprocess.py`)
- 품명 표기 5가지(`4G100`, `4G100 CUP #2`, `4G100 CUP (CV5)`, `4G 100 컵`, `4G 100 컵 #2`)를 같은 제품으로 본다.
- 로트번호의 차수를 뗀다: `6AB-1`, `6AB 1`, `6IT1` → `6AB`, `6IT`.
- 제품을 먼저 거른다. 같은 로트번호가 다른 제품에도 쓰인다.
- 벤토나이트 `28/1` 은 앞 숫자(투입량)만 쓴다. 측정값 0 은 결측으로 본다.

## 검증 방식

- **정답:** 로트 불량률이 기준을 넘으면 "불량 위험". 불량 실적이 로트 합계로만 기록되어 제품 단위 정답이 없다.
- **시간순 확장 검증:** 과거 로트로 학습하고 그 이후 로트 전체를 검증한다. 학습 구간을 늘려 가며 반복하고 평균한다. 시기마다 불량 수준이 달라, 무작위로 섞으면 "언제 생산했는가"가 새어 들어가 성능이 부풀려진다 (불량과 무관한 "생산 월"만으로 정확도 0.710).
- **비교 기준:** 모든 로트를 다수 쪽으로만 판정했을 때의 정확도. 정확도는 항상 이것과 함께 본다.
- **판정 임계값:** 학습 구간의 불량 비율만큼을 불량으로 판정하도록 학습 구간에서만 정한다.

## 결과 요약

**전체 기간 (529로트, 기준 2.95% 고정, 시간순 78회)**

| 입력 | 정확도 | 검출률 | AUC |
|---|---|---|---|
| 비교 기준 (다수 쪽) | 0.682 | | |
| 모래 시험 평균 9개 | 0.610 | 0.67 | 0.53 |
| + 최고·최저·편차·규격 이탈 비율 (46개) | 0.605 | 0.67 | 0.52 |
| + 직전 로트 대비 변화량 (55개) | 0.611 | 0.67 | 0.57 |
| 이항 회귀 (생산·불량 수량, 모래 9개) | 0.563 | | 0.45 |
| **직전 로트 불량률** | **0.750** | **0.81** | **0.77** |
| 모래 46개 + 직전 로트 불량률 | 0.724 | 0.79 | 0.72 |

**데이터 분석 (2024~2026)**
- 연도별 평균 불량률 2.86% · 2.98% · **4.64%**. 계획서의 기준 불량률 2.95% 는 2024~25 실적과 같다.
- 2026년 증가분은 몰드크랙(불량 중 4~5% → 15.5%)과 사혼입. 몰드크랙은 2025-12 부터 충진율 상승과 함께 늘었다 (월 단위 상관 +0.64).
- 같은 해 안에서는 모래 시험 항목과 불량률의 관계가 거의 없다 (대부분 ±0.1).
- 4G100 과 다른 제품의 불량률이 함께 움직인다 (월 단위 +0.54). 공장 공통 조건이 원인일 가능성이 크다.

**참고: 중간평가 보고서 기준 (2026-09-14 등록 데이터, 93로트)**
- 벤토나이트 투입량 1개로 정확도 0.796 (비교 기준 0.754), 검출률 62%.
- 이후 9월 로트의 불량 수량이 사후 수정되어 현재 DB 로는 0.519 로 재현되지 않는다.

## 주의

- DB 는 조회만 한다. 값이 사후에 바뀌므로 결과를 보고할 때 데이터 기준일을 함께 적는다.
- 노트북 1~4 의 설명 문구 일부는 2026-09 (93로트) 기준으로 쓰여 있다. 출력 수치는 실행 시점 데이터를 따른다.
- 저장소에 포함하지 않은 것: 원본·결과 데이터, 보고서 문서, 스트림릿 화면(`app.py`).
